## 1. Method

32 pilots, each audited solo by its own agent against a 10-dimension protocol (`PROTOCOL.md`, archived with the
audit evidence), with a full time/context budget per pilot — not split across agents (`docs/round2/HANDOFF.md`).
The protocol's ten dimensions (T1-T10): T1 tool contract and robustness (every tool: valid/missing/wrong-type
arguments, boundary `top_k`, unicode/control characters, no-init and bogus-session calls, repeat-call
determinism); T2 symbol accuracy against ground truth (>=25 symbols per pilot compared against the real,
independently-built package via the platform's own native tooling: `javap`, .NET reflection, Python
`inspect`/`pkgutil`, `.d.ts`, `go doc`, `cargo doc`, C++ public headers); T3 examples audit (every example
reachable through `find_examples`, run verbatim, classified runs-and-correct / runs-but-wrong-output /
does-not-compile / truncated / needs-undocumented-setup / not-runnable-by-design); T4 documentation audit
(`search_docs` per `content_type`, truncation/duplication/cross-contamination/dead-link checks, the
getting-started steps run verbatim); T5 product reference audit (all 8 `get_product_reference` sections checked
against reality: install, license, compatibility, formats, support/contributing links); T6 extended scenarios
(>=4 realistic escalating tasks using only MCP-sourced knowledge, verified independently); T7 honesty and
hallucination resistance (plausible non-existent classes/methods/features; `list_recent_changes` and
`report_index_freshness` checked against the real repository history and registry); T8 safety and hygiene
(untrusted-content flagging, prompt-injection echo, leaked paths/hostnames, latency over 20 sequential calls);
T9 cross-pilot consistency (same concepts named differently across sibling platforms of the same product); T10
agent usability (tool/parameter documentation sufficiency, ranking sanity, actionability).

## 2. Headline

**285 issues** across 32 pilots: **29 P0, 94 P1, 100 P2, 62 P3**. **No pilot scored above B+** (rating
distribution: B+ x1, B x6, B- x7, C+ x8, C x5, D x5). Zero pilots were left unverified this round — all 8
source-only pilots that round 1 left `BLOCKED_ENV` (tex/python, barcode/python, html/python, imaging/net, plus 4
C++ pilots) were built and run this round under explicit user authorization (`docs/round2/HANDOFF.md`).

Cross-cutting findings quoted verbatim from `docs/round2/HANDOFF.md`:

1. **`find_examples` is broken almost everywhere — fix the matcher, not the index (49 issues, `example_curator`)**:
   "Across nearly all 32 pilots, `find_examples` matches on example *title* words only, not body/code content.
   Typical finding: an example whose code literally contains `mapi_message`, `watermark`, `formula`, `Workbook`,
   `TextFragment` etc. is unreachable by that exact word." cells/java and slides/cpp return zero hits for every
   query tried.
2. **The self-reported "API-Coverage: N of N types (100%)" metric is not trustworthy (21 issues, `indexer`)**:
   "This number is always exactly 100% by construction in every pilot checked — it counts whatever got indexed
   and calls that the total, so it can never report less than 100%." Produces phantom symbols (3d/java: 37 of 74
   plausible-but-nonexistent names resolve as confident real symbols), duplicate-inflated counts (slides/python:
   every class double-indexed), undercounted real breakage (tex/python: claims "11 of 45 files could not be
   parsed"; real figure is 35 of 45), and wrong-vs-ground-truth counts (pdf/go: claims 285/285; `go doc -all`
   finds 234).
3. **Product-reference sections (`formats`/`limitations`/`install`) are the least reliable content layer (46
   issues, `product_reference_builder`)**: sections truncated mid-sentence, empty for one platform while a
   sibling platform of the same product extracts the equivalent README section fine (cells/cpp), and sections
   asserting specific, falsifiable, false claims about the installed package (3d/net claims PLY/RVM/AMF/HTML5
   export "work" — all four throw or write empty files).
4. **Silent-failure upstream library bugs that the MCP presents with no warning (45 issues,
   `upstream-library-bug`, but the fix is MCP-side)**: "These are defects in the Aspose libraries themselves, not
   fabrications by the MCP — but the MCP's job is to warn a coding agent before it hits them, and currently
   doesn't." Export/save silently writes the wrong thing with no exception (cells/java, cells/net write a full
   XLSX ZIP to a `.pdf`/`.csv`-named file); security-relevant (pdf/cpp's AES-256 encryption produces a file
   neither Aspose's own reader nor `pypdf`+`cryptography` can decrypt; imaging/net's indexed commit has 3 known
   DoS bugs fixed 5 commits later upstream).
5. **`search_symbols`/`get_symbol` fragment matching is inconsistently promised vs. delivered (15 issues,
   `mcp-ranking`, mostly `indexer`)**: "Tool descriptions promise 'type name or fragment' matching; in practice
   short prefixes miss real types unpredictably across many pilots" (pdf/typescript: `Doc` misses `Document`
   entirely; 3d/net and 3d/java: `Sc`/`Vec`/`Matri` all miss; slides/net: `Colo` misses but `Col` hits).

**Family-level finding, quoted verbatim**: "All 4 `3d/*` pilots tested (net, java, python, typescript) rated
**D, D, C, C+** — the four lowest/near-lowest scores of the whole portfolio. Every platform has broken or
entirely non-functional export for most of its documented formats... and both net and java separately show
symbol-index contamination (phantom types/inflated counts). This did not happen on any other product family to
this degree."
