# TC-057 — retired 2026-10-01

**Original goal:** run `run_extraction.py`'s cpp path for real against pdf/cpp's
actual public repository and pin the result as a reproducible offline fixture.

**Why retired, not fixed in place:** the taskcard schema caps a card at 3 attempts.
TC-057 used all 3, and each found a distinct, real C++ extraction-engine bug (not a
repeated guess):

1. Attempt 1 — `_node_name()`'s generic identifier-child fallback shadowed
   TC-010b's own cpp free-function branch. Fixed and accepted as **TC-058**.
2. Attempt 2 — `operator_name` node type missing from
   `_cpp_free_function_name()`'s checked tuple (C++ operator overloads). Fixed and
   accepted as **TC-059**.
3. Attempt 3 — `consolidate_classes()` silently discarded distinct same-named free
   functions across different files/namespaces. Fixed and accepted as **TC-092**
   (confirmed there to be "the exact bug that stalled TC-057 at its 3-attempt cap").

No fixture was ever committed under this card; `gatectl verify TC-057` was run once
more after all three fixes landed purely to produce an honest `FAILED_INTERNAL`
receipt (closing out the derived-state record truthfully) rather than leaving it
stuck at a stale `IN_PROGRESS`.

**What happens next:** pdf/cpp is still required for a complete product rollout
(operator decision, 2026-10-01) — cells/cpp only proved the C++ platform works in
general, it does not replace pdf/cpp's own place in the catalog. The same goal
continues under a fresh id, **TC-153**, now that all three real blockers are fixed.
